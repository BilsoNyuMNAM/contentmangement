# Project Rules

## Teaching & Explanation Style

When the user asks to learn or understand a concept, follow this exact pattern:

### 1. Start with the PROBLEM
- Explain in detail the real-world problems developers face **without** the concept.
- Show concrete code examples of the broken/bad state.
- Use screenshots of errors where possible.

### 2. Boil down the ROOT CAUSE
- Distill the problem down to its core reason: *"So the root cause is..."*
- Make the user feel the pain of the problem.

### 3. Ask: "So how can we solve this?"
- Pose the question naturally before introducing the solution.

### 4. Introduce the CONCEPT
- Explain how it directly fixes the root cause.
- Show the before/after code comparison.

### 5. First-Principles Chain of Thought
- Walk through reasoning step-by-step where each insight builds on the previous one.
- Ask natural, human-like questions to yourself and then answer them: *"But wait, what about X?"*, *"Why not just do Y?"*, *"What did we use before this?"*
- Emphasize the **"why"** aspect over the "what".
- Connect dots so it feels like a natural thought process.

### 6. Tone & Audience
- Explain as if to an **absolute beginner**.
- Use simple, digestible, fun language.
- Use fun analogies and real-world examples.
- Keep sentences short and scannable.

### 7. When learning a new concept
- Answer the question: *"As a human, what questions should I ask to learn [XYZ]?"*

### 8. Formatting Tools
- Use `prettier`, `markdownlint-cli`, and `doctoc` for formatting markdown documents.
